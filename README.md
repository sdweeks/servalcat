## 1. About this fork

Servalcat refines atomic models against diffraction data by maximum likelihood (amplitude- or
intensity-based), with restraints generated by [GEMMI](https://github.com/project-gemmi/gemmi) from the CCP4
monomer library. This fork is reduced to **crystallographic refinement that does not need the REFMAC5 binary
(or CCP4)** — X-ray data, and also neutron and electron diffraction — and extends it with TLS.

**What it does** (`servalcat refine_xtal`, formerly `refine_xtal_norefmac`, which still works as an alias)

* refinement of coordinates, isotropic or anisotropic B-factors, occupancies (including occupancy groups
  with constraints; experimental), deuterium fraction (neutron data) and TLS groups
* ML targets for amplitudes and intensities (merged or unmerged), twinned data, bulk-solvent and anisotropic
  scaling, anomalous scattering factors from the wavelength, riding hydrogen atoms
* geometry restraints from the monomer library (bonds, angles, torsions, chirality, planarity, van der Waals,
  stacking), local NCS restraints, jelly-body restraints, ADP restraints, external restraints (including
  ProSMART-style) through REFMAC-style keywords
* small-molecule data and models (`.hkl`, `.ins`, `.res`, `.cif`), unrestrained refinement
* geometry optimisation (`refine_geom`), ML parameter estimation and maps (`sigmaa`), French–Wilson conversion
  (`fw`) and utilities (`util`)

**New in this fork**

* **TLS refinement** — alternating, in the manner of REFMAC5: coordinates, isotropic residual B and occupancies
  are refined with the TLS parameters fixed, then T, L and S of every group are refined with the atoms fixed
  (`--tls`, `--tls_per_chain`, `--tls_file`, config section `refine.tls`). T and L are kept positive
  semi-definite, the total U of every atom stays positive definite, ADP restraints act on the residual B, and
  the output has total U in `ANISOU` with the TLS groups in `REMARK 3` / `_pdbx_refine_tls`.
* **Automated TLS group selection** — `servalcat util tls_select` divides every polymer chain into contiguous
  segments, reports how R-values change with the number of groups, recommends the lowest number of groups
  that gives the biggest improvement, and can instead be told how many groups each chain should have
  (`--ngroups A:4 B:2`); see [section 4](#4-tls-refinement-and-the-tls-selection-utility). The trial
  refinements run **in parallel**, one single-threaded process per available CPU, the next one starting as soon as
  one finishes (`-j N` / `--jobs N` to change the number; results do not depend on it).
* **Sequence assignment and mismatch feedback** — `--seq construct.fa` assigns the best-matching sequence to every
  protein, DNA and RNA chain, so SEQRES and `label_seq_id` include unmodelled termini, tags and gaps. The log lists
  every residue that differs from the sequence (useful while building into a map) and warns about register errors,
  chains with no acceptable sequence and ambiguous matches (`--seq_min_identity`, default 0.8; see
  [Sequence assignment](#sequence-assignment-and-mismatch-feedback)).
* **Restart after editing the model** — `prefix_tls.yaml` is written next to the refined model, with residue
  ranges and refined T, L, S, so TLS refinement continues (`--tls_file`) even if Coot or another program
  dropped the TLS records from the model file.
* **Corrected Fisher information for anisotropic B** — the curvature used for the off-diagonal elements
  (B12, B13, B23) was three times too large; with the fix, `--adp aniso` converges faster to the same result.
* **Smaller code base** — no REFMAC5 dependency, no cryo-EM code; a test suite (60 tests) covering the
  refinement options, TLS, the selection utility, sequence assignment and MTZ column selection.

**Removed compared with upstream**: cryo-EM single-particle programs (`refine_spa`, `refine_spa_norefmac`,
`fofc`, `fsc`, `trim`, `shiftback`, …), the REFMAC5 wrapper and controller (`refmacat`, `refmac5`,
`refine_cx`) and map utilities that only served cryo-EM. For those, use
[upstream Servalcat](https://github.com/keitaroyam/servalcat).

## 2. Example: isotropic refinement of coordinates and B-factors

Restrained refinement of the coordinates (geometry from the monomer library) and individual isotropic
B-factors against X-ray amplitudes with a free-R set, 10 cycles:

```shell
export CLIBD_MON=/path/to/monomers/        # the monomer library, see "Installation"

servalcat refine_xtal \
    --model model.pdb \
    --hklin data.mtz \
    --labin FP,SIGFP,FREE \
    --adp iso \
    --ncycle 10 \
    -o refined
```

* `--model`: the model (PDB or mmCIF; also small-molecule `.res`/`.ins`/`.cif`). `--hklin`: reflections (MTZ or
  mmCIF structure factors; merged or unmerged).
* `--labin F,SIGF,FREE`: the MTZ columns. It can be omitted: the columns are then selected automatically.
  The defaults are the amplitude columns `F`, `SIGF` and the test flags `FreeR_flag`; if those names are absent,
  the first amplitude (then intensity) columns found by type are used, and the first test-flag column among
  `FREE`, `RFREE`, `FREER`, `FreeR_flag`, `R-free-flags`, `FreeRflag`, `R_FREE_FLAGS`. `--prefer_intensity`
  selects intensities. The log lists the alternatives under "Finding possible options from MTZ" and the choice
  under "MTZ columns automatically selected". Use an intensity input as `--labin I,SIGI,FREE`.
* No `-s` (`--source`) is needed: the radiation source is `xray` by default. Give `-s neutron`, `-s electron` or
  `-s custom` for other sources.
* `--adp iso` is the default (`fix` keeps the B-factors, `aniso` refines anisotropic ADPs); the coordinates are
  refined unless `--fix_xyz` is given. Riding hydrogen atoms are generated by default (`--hydrogen all`) and
  are not written to the output unless `--hout` is given; use `--hydrogen no` to leave them out altogether.
* `-o refined`: output prefix (default: the model name + `_refined`).
* `--seq construct.fa` (optional): the sequence(s) of the construct in FASTA format. SEQRES and the residue numbering
  of the output then include unmodelled residues, and residues that differ from the sequence are listed in the log
  ([details](#sequence-assignment-and-mismatch-feedback)).

Output files:

| File | Content |
|---|---|
| `refined.pdb`, `refined.mmcif` | refined model |
| `refined.mtz` | map coefficients `FWT/PHWT` (2mFo-DFc), `DELFWT/PHDELWT` (mFo-DFc), `FOM`, `FC/PHFC`, `FCbulk`, free flags and ML parameters; opens directly in Coot |
| `refined_stats.json` | statistics of every cycle (R-values, CC, geometry, outliers) |
| `refined.log` | log, with tables for CCP4 `loggraph` |

On the small test peptide of this repository (`tests/5e5z`), this command gives Rwork 0.19 / Rfree 0.22 and
a bond-length r.m.s.d. of 0.017 Å after 10 cycles. The weight of the experimental data against the
restraints is chosen from the resolution and adjusted during refinement to keep the bond-length rmsZ between
0.5 and 1.0 (`--weight`, `--no_weight_adjust`, `--target_bond_rmsz_range`).

Ligands that are not in the monomer library need a restraint dictionary (e.g. from AceDRG):
`--ligand ligand.cif`. Without any restraints (small molecules): `--unrestrained --hydrogen no`.

## 3. All options of `refine_xtal`

`servalcat refine_xtal -h` (and `servalcat util tls_select -h`) prints the options in three tiers: *required*
arguments; *optional arguments with default values*; and *optional features that are off unless given* (refinement
options, TLS, sequence annotation, additional inputs, advanced options). The default of every option is stated in
its help line. The tables below are grouped by topic instead. Defaults are in parentheses. More detail:
[`docs/xtal.rst`](docs/xtal.rst), [`docs/source.rst`](docs/source.rst), [`docs/hydrogen.rst`](docs/hydrogen.rst),
[`docs/occ_refine.rst`](docs/occ_refine.rst) and [`docs/refmac_keywords.rst`](docs/refmac_keywords.rst).

### Required

| Option | Meaning |
|---|---|
| `--model FILE` | input model (PDB, mmCIF, or small-molecule `.res`/`.ins`/`.cif`) |
| `--hklin FILE` | input reflections (MTZ, mmCIF, or small-molecule `.hkl`/`.cif`) |

### Reflection data and test set

| Option | Meaning |
|---|---|
| `-s`, `--source {xray,neutron,electron,custom}` | scattering source (**default: `xray`**; give it only for another source).  `xray`: IT92 form factors (`--wavelength` adds f′ and f″); `neutron`: coherent scattering lengths; `electron`: Mott–Bethe; `custom`: coefficients given in the model file |
| `--labin F,SIGF,FREE` | MTZ columns of observations, sigmas and (optional) free flags. Amplitudes `FP,SIGFP`, intensities `I,SIGI`, and Friedel pairs `F(+),SIGF(+),F(-),SIGF(-)` / `I(+),SIGI(+),I(-),SIGI(-)` are accepted; Friedel pairs are merged for the target and used only for anomalous maps. Default: `F,SIGF,FreeR_flag` if present, otherwise selected automatically by column type |
| `--prefer_intensity`, `--prefer_anomalous` | when columns are selected automatically, prefer intensities / Friedel-pair columns |
| `--hklin_free FILE`, `--labin_free LABEL` | take test-set flags from another file (and column) |
| `--free N` | value of the free flag that marks the test set (default: guessed) |
| `-d`, `--d_min D`, `--d_max D` | resolution limits in Å (default: all data) |
| `--nbins N`, `--nbins_ml N` | number of resolution bins for statistics / for ML parameters (default: automatic) |
| `--use_in_est {all,work,test}` | reflections for estimating the ML parameters (default: `test`; `work` with `--twin`) |
| `--wavelength λ` | wavelength in Å for f′/f″ (X-ray only; default: from the file; `0` ignores it) |
| `--no_solvent` | no bulk-solvent contribution |
| `--use_fw` | debugging: refine against French–Wilson amplitudes but report intensity statistics |

### Restraints, ligands and hydrogen atoms

| Option | Meaning |
|---|---|
| `--monlib DIR` | monomer library (default: `$CLIBD_MON`) |
| `--ligand FILE [FILE ...]` | restraint dictionaries (cif) for residues that are not in the monomer library |
| `--newligand_continue` | make ad-hoc restraints for unknown ligands instead of stopping (not recommended) |
| `--unrestrained` | no positional restraints (hydrogen atoms are not generated) |
| `--hydrogen {all,yes,no}` | `all`: (re)generate riding hydrogens (rotatable ones excluded), `yes`: use those in the input, `no`: remove them (default: `all`) |
| `--hout` | write hydrogen atoms to the output model |
| `--refine_h` | let the data move hydrogen atoms (default: only the restraints do) |
| `--find_links` | find and add links (e.g. metal coordination) automatically |
| `--keywords KW [KW ...]`, `--keyword_file FILE` | REFMAC-style keywords (external restraints, restraint weights, torsion restraint rules; see [`docs/refmac_keywords.rst`](docs/refmac_keywords.rst)) |
| `--ncsr` | local NCS restraints |

| `--adaptive_restraint ALPHA` | scale the target of bond, angle, plane, torsion and vdW restraints by 1 + ALPHA·z² (robust) |
| `--vonmises` | experimental von Mises angle restraints |

| `--seq_min_identity X` | minimum fraction of modelled residues that must agree with a sequence for it to be assigned (default 0.8) |
| `--keep_entities` | do not regenerate entity and sequence information (SEQRES of the input is kept) |
| `--keep_charges` | use scattering factors of charged atoms (use with care) |

### Refinement control

| Option | Meaning |
|---|---|
| `--ncycle N` | number of cycles (10) |
| `--weight W` | starting weight of the experimental data against the restraints (automatic, from the resolution) |
| `--no_weight_adjust`, `--target_bond_rmsz_range MIN MAX` | do not adjust the weight during refinement / the bond rmsZ range that the adjustment aims at (0.5 1.0) |
| `--randomize RMSD` | shake the coordinates by this r.m.s.d. (Å) before refinement |
| `--bfactor B` | reset all B-factors to this value first |
| `--fix_xyz` | keep coordinates fixed |
| `--adp {fix,iso,aniso}` | B-factors: fixed, isotropic (`iso`), anisotropic. With TLS, `iso` means isotropic *residual* B |
| `--refine_all_occ` | refine the occupancy of every atom (experimental; groups and constraints go in the config file) |
| `--allow_unusual_occupancies` | allow negative or larger-than-one occupancies in the input |
| `--refine_dfrac` | refine the deuterium fraction (neutron data only) |
| `--twin`, `--twin_mlalpha` | twin refinement (operators found automatically); optimise the twin fractions by ML instead of estimating them |

| Option | Meaning |
|---|---|
| `--adpr_weight W` | weight of the ADP restraints (1) |
| `--adp_restraint_mode {diff,kldiv}` | difference of B or Kullback–Leibler divergence between neighbouring atoms (`kldiv`) |
| `--max_dist_for_adp_restraint D` | longest distance of an atom pair that is restrained (4.0 Å) |
| `--adp_restraint_power P`, `--adp_restraint_exp_fac F` | the weight of pairs that are not bonded decays as exp(−d^P·F) (P = 4, F = 0.011271) |
| `--adp_restraint_no_long_range` | restrain only atom pairs that are linked by bond, angle, torsion or chirality restraints (not plane, van der Waals or stacking pairs) |
| `--occr_weight W` | weight of the occupancy restraints (0) |

### TLS (details in [section 4](#4-tls-refinement-and-the-tls-selection-utility))

| Option | Meaning |
|---|---|
| `--tls` | TLS refinement; groups from `refine.tls.groups` in the config, else from the input model |
| `--tls_per_chain` | TLS refinement with one group per chain (when no groups are defined) |

| `--tls_ncycle N` | TLS steps per refinement cycle (1) |

### Output

| Option | Meaning |
|---|---|
| `-o`, `--output_prefix PREFIX` | prefix of the output files (model name + `_refined`) |

### Configuration file (`--config`)

Settings that are awkward on the command line go into a yaml file. All keys with their defaults:

```yaml
    dfrac: {include: [], exclude: [], exclude_restraint: []}
  vdw_exclusion: {selections: [], pair_selections: []}
  occ_groups: []                # - {id: 1, selections: ["//A/338/*:A"]}
  occ_group_constraints: []     # - {ids: [1, 2], complete: true}
  occ_group_const_mu: 10.0      # augmented Lagrangian parameters
  occ_group_const_mu_update_factor: 1.1
  occ_group_const_mu_update_tol_rel: 0.25
  occ_group_const_mu_update_tol_abs: 0.01
  geom_weights:                 # weight 1 each; adaptive_weight is ALPHA of --adaptive_restraint
    bond: {weight: 1.0, adaptive_weight: 0.0}
    angle: {weight: 1.0, adaptive_weight: 0.0}
    tors: {weight: 1.0, adaptive_weight: 0.0}
    chir: {weight: 1.0, adaptive_weight: 0.0}
    plane: {weight: 1.0, adaptive_weight: 0.0}
    vdw: {weight: 1.0, adaptive_weight: 0.0}
    ncs: {weight: 1.0}
    stack: {weight: 1.0}
  local_geom_weights: []        # - {sel: "//A/338/*", w: 2}
  local_adpr_weights: []        # - {sel: "//A/338/*", w: 5}
  tls:
    groups: []                  # - {id: 1, selections: ["//A/4-80/*"]}, optionally with origin, T, L, S

  initialisation:               # set values before refinement, e.g. adp: {"*": 30}

    occ: {}
    dfrac: {}
  write_trajectory: false
  exte_files: []                # json files with external restraints (written as PREFIX_exte.json)
```

### Sequence assignment and mismatch feedback

By default the SEQRES records and `label_seq_id` of the output are generated from the **modelled** residues, so unmodelled
termini, tags and gaps are not represented. With `--seq construct.fa` the full construct sequence is used instead:

```
servalcat refine_xtal --model model.pdb --hklin data.mtz -s xray --seq construct.fa ... 
```

* The FASTA file may contain any number of protein, DNA and RNA sequences (headers are used as names). Each polymer chain
  is aligned to every sequence of its own type and the best match is taken. A sequence containing `U` is never used
  for DNA, nor one containing `T` for RNA, so DNA and RNA chains with the same base order cannot be mixed up.
  Sequences in the file that match no chain are ignored.
* A sequence is assigned only if at least `--seq_min_identity` (default 80%) of the modelled residues agree with it.
  Otherwise the chain keeps the modelled sequence and the log says which sequence was closest and how similar it was.
* Residues are numbered (`label_seq_id`) by the alignment, so gaps and unmodelled ends are correct in SEQRES and in the mmCIF output.

The log (and therefore every re-run after you edit the model in Coot) contains a table and the differences found:

```
Sequence assignment from construct.fa (minimum identity 80%)
 chain(s)   type     sequence         length modelled identity mismatches
 A          protein  construct           156      144    99.3%          1
    sequence positions not modelled (chain A): 1-6, 57, 139-142, 156

Residues that differ from the assigned sequence (1); mutations, or residues built/typed wrongly:
   A/50     model GLU  sequence ALA  (construct)
```

This applies when you build into a map: a residue of the wrong type is listed with its number, the model residue
and the sequence residue, so it can be checked in the map. Notes on what is and is not counted:

* Modified residues that replace a standard one (MSE for MET, ...) count as agreeing; unknown residues (`UNK`, or `N` in nucleic
  acids) are listed separately and do not lower the identity.
* A **register error** (a stretch built one or two residues out of register) usually does not appear as many
  mismatches, because the alignment explains it as a gap. It is therefore reported explicitly: sequence skipped between
  two bonded residues, modelled residues with no counterpart in the sequence, or a stretch that agrees with the sequence
  after a shift. These appear as `WARNING:` lines.
* Two sequences fitting equally well, or a chain with no acceptable sequence, are also warned about.

`servalcat util seq --model model.pdb --seq construct.fa` prints the alignments themselves, if you want to look at them.

Occupancy refinement is described in [`docs/occ_refine.rst`](docs/occ_refine.rst).

## 4. TLS refinement and the TLS selection utility

### TLS refinement

TLS models the collective motion of rigid groups of atoms: U<sub>total</sub> = U<sub>TLS</sub>(T, L, S) + B<sub>residual</sub>/8π². Units follow
the PDB, REFMAC5, Phenix and GEMMI: T in Å², L in deg², S in Å·deg; the origin of each group is its centre of mass.
Define groups in a config file

```yaml
refine:
  tls:
    groups:
      - {id: 1, selections: ["//A/4-80/*"]}
      - {id: 2, selections: ["//A/81-152/*", "//B/*"]}   # a group may have several selections
```

and run

```shell
servalcat refine_xtal --model model.pdb --hklin data.mtz -s xray --config tls.yaml --ncycle 20 -o refined_tls
```

Use 20 or more cycles. TLS requires an isotropic residual B (`--adp iso` or `--adp fix`, not `aniso`). Groups
may also come from the TLS records of the input model, or be one per chain (`--tls_per_chain`). Atoms that are
in no group keep an isotropic B. Output: total U in `ANISOU`, B-factor column = isotropic equivalent, TLS groups
in `REMARK 3` and `_pdbx_refine_tls`, and `refined_tls_tls.yaml` (see below).

### Automated selection of TLS groups: `servalcat util tls_select`

```shell
servalcat util tls_select --model refined.pdb --hklin data.mtz -s xray --labin FP,SIGFP,FREE -o tlssel
servalcat util tls_select ... -j 8     # at most 8 trial refinements at the same time (default: all available CPUs)
```

Give it an isotropic model refined with `refine_xtal`. Data, model and monomer-library options (including `--seq`)
are those of `refine_xtal`. Every polymer chain is divided into contiguous segments (waters and ligands are never included, and
a group never spans two chains).

**How it works.** For N = 1, 2, … groups per chain, dynamic programming finds the best division of each chain, using
the decrease of the likelihood target that TLS is predicted to give for every possible segment (calculated from the
per-atom gradient and Fisher matrix; it correctly places the boundary of two simulated domains). Each N is then
evaluated by a short refinement with the coordinates fixed (`--tls_cycles`, 8) in which residual B and TLS are
refined, using the same code as `refine_xtal`; N = 0 is the same refinement without TLS.

**Parallel trials.** The trial refinements (N = 0 … `--max_groups`) are independent and each uses a single CPU thread, so
they run in parallel: by default one process per CPU available to the program (CPU affinity and container CPU quota are
respected, and never more processes than trials). When a trial finishes the next one starts, so with 9 trials on
4 CPUs the machine stays busy until the last ones are running. Results are identical to a serial run. Each process holds
its own copy of the data and restraints, so for a large structure on a machine with little memory reduce the number with
`-j N` (`-j 1` runs the trials one after another). For example, a scan of 0–4 groups on the test data took 94 s serially and
38 s on 4 CPUs (the trials alone: 83 s of work in 28 s).

**R-values per number of groups.** The log shows a table, a bar graph and a CCP4 loggraph table; the same data are
in `PREFIX_scan.csv` and `PREFIX_scan.json` (which also holds the residue ranges of every N), and
`PREFIX_scan.png` if matplotlib is installed. Example, for data simulated from two rigid domains:

```
 N  groups  params  Rwork  Rfree  d_Rfree     -LL  dp_score
 0       0       0 0.0556 0.0650      NaN 89327.5    0.0000
 1       1      20 0.0345 0.0414   0.0236 76419.3 2439.7
 2       2      40 0.0234 0.0284   0.0130 66786.3 3016.4
 3       3      60 0.0230 0.0280   0.0004 66441.3 3120.2
 4       4      80 0.0229 0.0278   0.0002 66254.0 3206.3

Recommendation: 2 group(s) per chain.
  chain A: 4-80, 81-152
```

`d_Rfree` is the decrease of Rfree (Rwork if there is no test set) from N−1 to N. `dp_score` only ranks divisions with
the same N; it is not comparable with the change of −LL.

**Recommendation (conservative).** TLS is recommended at all only if one group per chain lowers R by at least
`--min_delta` (0.001). The number of groups is then the lowest N ≥ 2 whose jump d(N) is within `--tie` (0.25) of the
biggest jump among N ≥ 2 — the lowest number of groups that gives the biggest improvement. If no further group
reaches `--min_delta`, one group is recommended. When the chosen jump is small the program says that the evidence
is weak (on real data the curve is often smooth with no clear step; compare with 1 group and prefer fewer groups at
lower resolution).

**Choosing the numbers yourself.** `--ngroups` skips the scan; the program finds the best residue ranges for the
requested numbers per polymer chain and writes them:

```shell
servalcat util tls_select ... --ngroups 4          # 4 groups in every polymer chain
servalcat util tls_select ... --ngroups A:4 B:2    # per chain (chains not mentioned get 1 group)
servalcat util tls_select ... --ngroups A:3 --no_eval   # ranges only, no R-values
```

**Options**

| Option | Meaning |
|---|---|
| `--ngroups N` or `CHAIN:N ...` | do not scan; use these numbers of groups |
| `--no_eval` | with `--ngroups`: do not run the refinement that gives R-values |
| `--max_groups N` | largest number of groups per chain in the scan (8) |
| `--min_residues N` | smallest group, in residues (10); a chain too short for N groups gets as many as fit |
| `-j`, `--jobs N` | number of trials run in parallel (default: number of available CPUs) |
| `--tls_cycles N` | cycles of the refinement that evaluates each N (8) |
| `--min_delta X` | smallest decrease of R that counts as an improvement (0.001) |
| `--tie X` | jumps within this fraction of the biggest one are equivalent; the lowest N among them is chosen (0.25) |
| `-o PREFIX` | output prefix (model name + `_tlsselect`) |

**Output files**: `PREFIX_tls.yaml` — the recommended (or requested) groups, for `refine_xtal --tls_file`;
`PREFIX_tls_N<N>.yaml` — the groups of every scanned N; `PREFIX_scan.csv`/`.json`/`.png`; `PREFIX_trials/` — files of
the trial refinements.

**Workflow**

```shell
# 1. isotropic refinement
servalcat refine_xtal --model start.pdb --hklin data.mtz -s xray -o iso
# 2. choose the groups; read the R-values (iso.pdb is the refined model)
servalcat util tls_select --model iso.pdb --hklin data.mtz -s xray -o sel
#    or force the numbers: ... --ngroups A:3 B:3
# 3. TLS refinement with the chosen groups
servalcat refine_xtal --model iso.pdb --hklin data.mtz -s xray --tls_file sel_tls.yaml --ncycle 20 -o tls1
# 4. after rebuilding in Coot, continue from the groups and T, L, S of the previous refinement
servalcat refine_xtal --model coot_edited.pdb --hklin data.mtz -s xray --tls_file tls1_tls.yaml --ncycle 20 -o tls2
```

Keep the groups fixed during a refinement campaign (changing them makes R-values of different rounds
incomparable) and select again only after a major rebuild or if the data change. In step 4, `tls1_tls.yaml`
(written by step 3) restarts from the previous T, L and S; B-factors in the model are taken as total
(`input_b: total`). Residue ranges follow the edits: residues added inside a range join the group; ligands and
waters outside every range keep an isotropic B.

**Limitations**: the scan uses the same N for every chain (use `--ngroups` for chain-specific numbers); the ranges are
gemmi selections (`//A/4-80/*`), so a non-polymer residue numbered inside a range is included; the scan costs about
(N<sub>max</sub> + 1) × `--tls_cycles` refinement cycles, so use `--max_groups`/`--tls_cycles` to shorten it for large structures.

## 5. Installation

This fork is installed from source (a compiled C++ extension is built, with GEMMI).

### Requirements

| | |
|---|---|
| Operating system | Linux or macOS in principle; built and tested only on Ubuntu 24.04 (x86-64) |
| Python | 3.10 or newer (tested with 3.13) |
| Python packages | `numpy`, `scipy`, `pandas`, `omegaconf==2.3.0`, `packaging`, `nanobind-backend` — installed automatically |
| Build tools | a C++17 compiler (tested with GCC 13), CMake ≥ 3.15 (3.28), Ninja or make, git. `scikit-build-core` and `nanobind` ≥ 3.1 are fetched by pip during the build |
| Eigen | Eigen 3.4 headers: see below |
| Internet during the build | CMake downloads [GEMMI](https://github.com/project-gemmi/gemmi) (version 0.7.6-dev; the pinned commit is in `CMakeLists.txt`), which is built into the package. For an offline build place a GEMMI checkout in a `gemmi/` directory of the source tree |
| **Monomer library** | required at run time for restrained refinement, see below |

**Not required**: CCP4, REFMAC5, a GPU or network access when running.

### Install

```shell
git clone --recurse-submodules --branch claude/relaxed-ramanujan-e4ko9y https://github.com/sdweeks/servalcat.git
cd servalcat
pip uninstall servalcat    # only if upstream Servalcat is installed (same package name)
pip install .
```

`--branch claude/relaxed-ramanujan-e4ko9y` selects the branch that contains the features described above; the `main`
branch of this repository is still identical to upstream. (Once the branch has been merged into `main`, leave the
option out.) If you already cloned the repository: `git fetch origin && git checkout claude/relaxed-ramanujan-e4ko9y`
and `git submodule update --init`.

`--recurse-submodules` fetches Eigen into `eigen/` (from <https://gitlab.com/libeigen/eigen.git>). If you cloned
without it, run `git submodule update --init`, or install Eigen 3.4 with your package manager instead — then
CMake finds it by itself (`sudo apt install libeigen3-dev`, `brew install eigen` or `conda install eigen`; the apt
package is what was used for testing). Use a virtual environment or conda environment if you do not want to
install into the system Python. The build takes several minutes.

Check the installation (`tls_select` exists only in this fork, so it shows that the right version is installed):

```shell
servalcat -v
servalcat refine_xtal -h
servalcat util tls_select -h
```

### Monomer library

Restrained refinement needs the CCP4 monomer library (restraint dictionaries for the residues and ligands in the
model). Either

* use the copy of an existing CCP4 installation — its setup script sets `$CLIBD_MON` — or
* download it from <https://github.com/MonomerLibrary/monomers> (about 0.8 GB):

```shell
git clone --depth 1 https://github.com/MonomerLibrary/monomers.git
export CLIBD_MON=$PWD/monomers/        # add this line to ~/.bashrc or ~/.zshrc
```

The library is found through `$CLIBD_MON` or `--monlib /path/to/monomers/` (every command that needs restraints has
this option). Without it, Servalcat warns that `CLIBD_MON` is not set and stops at the first residue it has no
restraints for. Residues and ligands that are not in the library need a dictionary from AceDRG or similar
(`--ligand dict.cif`). Unrestrained refinement (`--unrestrained`) does not need the library.

### Tests

```shell
pip install pytest
CLIBD_MON=/path/to/monomers/ python -m pytest -p servalcat tests/
```

(`-p servalcat` imports Servalcat first, which makes its bundled GEMMI the `gemmi` module.) The full run takes
about 6 minutes. If you use Servalcat from Python: `import servalcat` before `import gemmi`, and
`from servalcat import utils` before importing other submodules.

### Troubleshooting

* *CMake cannot find Eigen3*: the `eigen/` submodule is empty — see above.
* *`omegaconf` fails to install because `antlr4-python3-runtime` (a dependency of `omegaconf==2.3.0`) does not build*:
  this happened here with pip on Python 3.13, where building its source archive failed. The workaround that worked: download
  the `antlr4-python3-runtime==4.9.3` source archive, copy its `src/antlr4` directory (pure Python) into your `site-packages`,
  install the other dependencies yourself, and install this fork with `pip install --no-deps .`.
* *`CLIBD_MON is not set` / unknown residues*: see Monomer library.
